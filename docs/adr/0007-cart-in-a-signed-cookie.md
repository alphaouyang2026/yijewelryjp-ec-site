# 购物车：保存在签名 cookie 里，每次读取都按商品目录重新校验

规格要求购物车完全保存在 API 签发的签名 cookie 里，服务器不存储：顾客没有账号，为匿名的购物车建 item 还要清理过期数据，而 cookie 本身就满足"下次在同一设备上再来时还在"。cookie 是 `__Host-yi_cart`，由 `interface/signed-cookies.ts` 读写，和店主会话一样是 HTTP-only、Secure、SameSite=Lax，用由现有签名密钥和 cookie 名派生的密钥签名（不需要新的机密，会话 cookie 的值也冒充不了购物车）。每次修改都重写整个购物车，有效期重新算 30 天；查看从不写 cookie；购物车变空时清除 cookie。签名不对、内容不是购物车的格式时，当作空购物车，不报错。

内容是 `{ v: 1, l: [[商品 slug, SKU, 数量, 记下的价格], …] }`：键名尽量短，最多 20 行（规格的上限，保证结账能在一个 DynamoDB 事务里完成）。行按"商品 slug + SKU"识别，这样每次查看只需按 slug 读购物车里的商品（最多 20 次 `GetItem`），不用读整个 `PRODUCT` 分区（ADR 0005）；页头的件数让每个前台页面都查看一次购物车。SKU 是自由文本，所以 HTTP 接口里的行用不透明的 `lineId`（`<slug>/<SKU>` 的 base64url）表示，前端只回传它，不自己拼。

cookie 里只有顾客的选择，价格和可售数都不可信：API 每次返回购物车都按当前商品目录重新校验，附上购物车提示，并算出小计、运费和合计，前端只显示。商品下架、售罄的行留在购物车里但不计入合计，直到顾客删除；可售数少于数量时按可售数显示和计算，cookie 里的数量不改。

## 改价：和该行记下的价格比较

每行记下顾客最后一次加入或修改该行数量时的单价。查看时当前价格和它不同，就附上改价提示（带原来的价格），合计按当前价格算。提示一直显示，直到顾客再次加入这个规格或修改这一行的数量，这时记下的价格换成当前价格；删除其他行不会。因为查看从不写 cookie，刷新页面或页头的查询不会在顾客看到之前把提示"消耗"掉。

## 不用 CSRF 令牌

后台修改数据要带会话的 CSRF 令牌，购物车接口不要求。修改请求的请求体必须是 JSON：别的网站的 HTML 表单发不出 `application/json`，其他内容类型都按无效输入返回 400；别的来源用 `fetch` 发 JSON 或 PUT、DELETE 需要 CORS 预检，而 API 从不允许跨域；cookie 又是 SameSite=Lax，别的网站发起的子请求不带它。即使被改了，后果也只是顾客的购物车内容变了，付款前顾客会看到。顾客没有会话，要用令牌还得另发一个 cookie 并让每个页面先取令牌，不值得。**以后如果 API 开放 CORS 或接受表单请求体，要重新考虑这一条。**

## 运费：店铺设置的接缝，#16 之前用配置的默认值

运费和免运费门槛从店铺设置读取（`store/domain/store-settings.ts` 的 `StoreSettings`，订单上下文通过 `store` 的应用层查询拿到）。后台能编辑店铺设置之前（#16），生产用的实现 `configuredStoreSettings` 直接返回配置的值：默认运费 ¥800、门槛 ¥20,000（暂定，待店主确认），入口可以用环境变量 `SHIPPING_FEE_YEN`、`FREE_SHIPPING_THRESHOLD_YEN` 覆盖。它不是测试替身（ADR 0002），测试只是给它固定的值，让边界值测试写明金额。#16 换成 DynamoDB 上的实现，没设置时仍用同样的默认值；订单上下文和接口不变。"达到门槛免运费、没有可售的行时运费为零"这条规则在订单上下文的领域层，结账（#12）计算订单合计时沿用。

## Consequences

- 结账（#12）复用同一个 cookie 和同样的重新校验，付款完成后由感谢页清除它。
- 浏览器限制一个 cookie 约 4 KB。20 行用常见长度的 slug 和英数字 SKU 约 1.5 KB，用满 80 字符的 slug 和 64 字符的英数字 SKU 约 3.8 KB；cookie 里的非 ASCII 字符要经过 URL 编码（一个日文字符 9 字节），SKU 用日文时 20 行可能超出上限，浏览器会丢弃这个 cookie。所以加入商品和修改数量时 API 先按实际写出的字节数（`signed-cookies.ts` 的 `byteLength`：cookie 名加 URL 编码后的 JSON 和签名）估算，超过 4000 字节（留出余量）就拒绝，返回 409 `cart_too_large`，不改购物车、不写 cookie；这样购物车不会因为 cookie 太大被浏览器悄悄丢掉。它和已有 20 行时的 409 `cart_full` 分开，前端才不会在不到 20 行时说"最多 20 种"。修改数量也要检查：新的数量或记下的价格位数多了，cookie 也会变长几个字节。删除只会让 cookie 变短，不做这个检查。
- 商品不存在的行（商品从不删除，只有重置表后才会发生）不显示，下次修改时从 cookie 中去掉。

## Considered Options

- **服务器保存购物车（DynamoDB item，cookie 只放 id）**：规格已经排除；还要处理过期清理，每次查看多一次读取。
- **行只按 SKU 识别**：SKU 在目录内唯一，但从 SKU 找商品要读整个 `PRODUCT` 分区或增加索引 item。
- **cookie 不记价格，或查看时更新记下的价格**：前者发现不了改价；后者要让查看写 cookie，提示在顾客看到之前就可能消失。
